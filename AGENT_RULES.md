# Agent Rules

Rules for all OpenClaw agents working on Budget Shield.

## Project Rules

### One Active Project Only
BudgetShield_CLEAN is the only active project. Do not create or work on other repositories.

### One Ordered Task at a Time
Follow the TASK_QUEUE.md. Do not skip ahead.

### Never Rebuild Without Authorization
Never rebuild the whole application without written authorization from Scott.

### Never Create Another Repository
Do not create BudgetShield-v2, BudgetShield-NEW, or any other repo.

### Never Create Another Project Folder
All work stays in BudgetShield_CLEAN.

### Never Recover Legacy Code
Forbidden projects:
- BudgetBuddy
- Budget-App
- toons-treasure-hunt

Do not search, inspect, copy, reference, restore, merge, or salvage code from these.

### Never Claim Completion From Compilation Alone
A successful build does not mean a task is complete.

### Never Claim Visual Accuracy Without Screenshots
Visual tasks require screenshot evidence compared to reference images.

### Never Claim Functionality Without Testing
Every visible control must be tested.

### Never Leave Dead Controls in Beta
No placeholder buttons that do nothing in a claimed beta build.

### Never Hide Failures
Report crashes, build failures, and test failures honestly.

### Never Replace Working Features
Do not "fix" things outside the assigned task scope.

### Never Change Product Vocabulary
Safe Now is Safe Now. Do not rename it.

### Never Alter Reference Images
The reference images in docs/reference/ are immutable.

### Never Mark Complete Without Evidence
Tasks require verifiable evidence.

## Document Rules

### Read Before Working
Read all project-control documents before each task.

### Update After Completing
Update PROJECT_STATE.md, CHANGELOG.md, and relevant docs after every completed task.

## Git Rules

### Clean State Required
Working tree must be clean before starting a task.

### Commit Message Format
`Task N: Brief description`

### Push Required
Commits must be pushed to remote and verified.
